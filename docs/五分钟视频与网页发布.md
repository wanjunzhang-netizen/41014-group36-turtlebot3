# 五分钟演示视频：录制、讲解和嵌入网页

目标时长4分50秒左右。录制真实仿真，保留一次完成任务的全过程和至少一次扰动试验；屏幕同时显示模型、传感器、估计与真实轨迹、不确定性。界面内容太小时优先放大，不必录安装过程。用已有录屏软件录整个屏幕，避免仅录到一个窗口；先录10秒并回看声音和画面。关闭私人窗口和通知。

运行命令（VS Code 终端，项目根目录）：

```powershell
.\.venv\Scripts\python.exe main.py --seed 0
.\.venv\Scripts\python.exe main.py --seed 0 --camera-dropout 4
```

两个试验分别运行，关闭第一组窗口后再运行第二个。保存结果后将需要保留的证据另存，重复同参数会覆盖输出。仿真时间不等于真实录像时间；电脑较慢时录制原始完整过程，再适当加速并明确标注“2× playback”等。不要剪掉失败却声称连续成功。两次试验都必须看得到最终状态。视频不必逐字背诵表格。

## 把视频放入项目页（推荐 MP4）

1. 将最终视频导出为浏览器可播放的 H.264 MP4，建议720p/30fps，保证图中文字可读，总时长≤300秒。
2. 文件命名 demo.mp4，放到 `website/static/videos/demo.mp4`。不要把原始大视频也放到仓库。
3. 打开 website/config.js，将 videoFile 改成 `"static/videos/demo.mp4"`；youtubeId 保持空字符串。repository 保留自己的仓库地址。
4. 本地 HTTP 预览，确认视频实际能播放。播放器会对超过300秒的本地视频显示提示，但你仍应自己检查时长。
5. 按上传指南第6节提交并发布两个分支。等待 Pages 部署，在真实网页再检查播放。
6. README 顶部 Demo video 填 `https://你的用户名.github.io/41014-group36-turtlebot3/#demo`。

GitHub 普通 Git 上传拒绝超过100 MiB的单文件，超过50 MiB会警告；网页手动上传上限25 MiB。建议把成片压到50 MiB以下；如果太大不要直接提交后再删除（大文件仍在Git历史里），先压缩或采用下面的视频托管方式。

## 视频过大时：嵌入 YouTube

可以将自己的成片上传 YouTube，设置为 Unlisted（不公开列出），不能设 Private。取得 watch?v= 后的11位视频ID，填入 config.js 的 youtubeId；videoFile 设为空。网页会嵌入播放器。用未登录窗口确认老师能播放。此方式视频显示在 GitHub Pages 项目页内，但视频文件托管于 YouTube；若老师明确要求视频文件必须进仓库，则采用压缩MP4方式。

## 四幅图怎样说

- Camera: This is the image used to detect the marker. 相机图：用于识别标记的实际图像。
- LiDAR: These points show nearby surfaces relative to the robot. Horizontal is right; vertical is ahead, in metres. 雷达图：机器人周围表面，横轴向右、纵轴向前，单位米。
- Path: These are the true and estimated paths in the fixed frame established at first observation. Both axes are position in metres. 轨迹图：首次观察建立的固定坐标系中真值与估计路径，两轴位置单位米。
- Error: Horizontal is time in seconds; vertical is metres. Blue is actual position error, used only for evaluation. Dashed is estimated uncertainty, not an exact 95% bound. 误差图：横轴秒、纵轴米，蓝线实际误差只用于评估，虚线估计不确定性，不是严格95%置信边界。
